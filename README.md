# White-P — اجرای محلی مدل و گفت‌وگوی همتا‌به‌همتا

## هدف محصول

White-P با هدف ساخت دو برنامه طراحی می‌شود: یک میزبان ویندوز برای اجرای مدل‌های هوش مصنوعیِ قابل اجرا روی سخت‌افزار خود میزبان، و یک کلاینت اندروید برای فرستادن درخواست به میزبان‌های در دسترس. مسیر هدف، ارتباط مستقیم همتا‌به‌همتا (P2P) با شناسه/هش موقت برای هر درخواست است؛ سرویس مرکزی نباید متن درخواست، پاسخ تولیدشده یا تاریخچهٔ گفت‌وگو را دریافت یا نگهداری کند.

این README شرح هدف نسخهٔ نخست و وضعیت واقعی مخزن است؛ ادعای آماده‌بودن محصول نیست.

## اجزای هدف نسخهٔ نخست

- **میزبان ویندوز:** رابط WPF با C# و .NET LTS؛ کشف ظرفیت واقعی دستگاه و اتصال به موتور استنتاج محلی.
- **کلاینت اندروید:** Kotlin، Jetpack Compose و Gradle؛ ایجاد درخواست، انتخاب میزبان و نمایش نتیجه.
- **قراردادهای مشترک:** فایل‌های منبع Protobuf برای پیام‌های نسخه‌دار بین دو برنامه.
- **موتور محلی:** اتصال به backend واقعی روی همان دستگاه میزبان، با کنترل خطا، لغو و health check.
- **انتقال P2P:** اتصال مستقیم به‌عنوان مسیر پیش‌فرض داده؛ هر سرویس کمکی احتمالی فقط برای معرفی/هماهنگی اتصال، نه پردازش درخواست هوش مصنوعی.
- **آزمون و CI:** آزمون‌های واحد و یکپارچه‌سازی، build قابل‌تکرار و کنترل‌های خودکار در GitHub Actions.

این موارد محدودهٔ هدف هستند؛ وجودشان در این فهرست به معنی پیاده‌سازی‌شدن آن‌ها نیست.

## محدودهٔ نسخهٔ نخست

نسخهٔ نخست باید بتواند میزبان را اجرا کند، backend محلی واقعی را شناسایی کند، فقط یک inference هم‌زمان برای هر میزبان بپذیرد، درخواست را از کلاینت اندروید به میزبان برساند و پاسخ را بدون عبور متن درخواست از یک API مرکزی برگرداند. خطا، لغو، deadline، مدل ناسازگار و میزبان مشغول باید وضعیت‌های قابل‌تشخیص داشته باشند.

مواردی مانند بازارچهٔ مدل کامل، اجرای ابزارهای عامل با دسترسی گسترده، چند inference هم‌زمان روی یک میزبان و هرگونه ادعای امنیتی تأییدنشده خارج از محدودهٔ نسخهٔ نخست‌اند.

## وضعیت فعلی مخزن

در commit فعلی، ابزار اعتبارسنجی گراف، آزمون‌های Python و workflow کیفیت گراف موجودند. پروژهٔ اجرایی WPF، پروژهٔ Android Gradle، solution دات‌نت و قراردادهای Protobuf هنوز در مخزن ایجاد نشده‌اند. بنابراین فعلاً build محصول، بستهٔ نصب ویندوز/اندروید یا تبادل P2P موفق وجود ندارد و این README آن‌ها را ادعا نمی‌کند.

CI موجود در حال حاضر آزمون‌ها و کنترل‌های Python/گراف را اجرا می‌کند؛ این به‌تنهایی اثبات build یا عملکرد محصول نهایی نیست. مسیرهای واقعی build باید پس از ایجاد پروژه‌های متناظر اضافه و در CI اجرا شوند.

## اصول حریم خصوصی و امنیت

- متن درخواست و پاسخ نباید به سرویس مرکزی ارسال یا در log عادی ثبت شود.
- هش/شناسهٔ درخواست باید موقت و غیرقابل‌استفاده به‌عنوان شناسهٔ دائمی کاربر باشد.
- هر ادعای «محلی»، «P2P»، «رمزگذاری‌شده» یا «بدون ذخیره‌سازی» تنها پس از آزمون یا بررسی قابل‌تکرار قابل تأیید است.
- تا زمانی که آزمون‌های متناظر اجرا نشده‌اند، این موارد الزامات طراحی‌اند، نه ادعاهای اثبات‌شدهٔ محصول.

## توسعه و آزمون فعلی

با Python 3.13 می‌توان کنترل‌های فعلی مخزن را اجرا کرد:

```bash
python -m unittest discover -s tests -v
python -m compileall -q tools tests
python tools/graph_guard.py "step three/project-graph.md" --repo-root .
```

این دستورها کنترل‌های موجود مخزن را می‌آزمایند؛ در وضعیت فعلی جایگزین build میزبان ویندوز، build اندروید یا آزمون P2P نیستند. دستورهای build محصول پس از اضافه‌شدن پروژه‌های واقعی ثبت خواهند شد.
