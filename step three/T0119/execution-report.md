# T0119 execution report — design/policy task accepted

- **Task:** define a safe boundary for any future encrypted relay byte path and explicitly record the metadata visible to a relay.
- **Accepted commit:** `V 3.0.359` — [`4c568f4aa6485bd9c54a082841eabf5dc9b30ef7`](https://github.com/artinrahimii/project/commit/4c568f4aa6485bd9c54a082841eabf5dc9b30ef7).
- **Decision:** `docs/decisions/ADR-0004-encrypted-relay-boundary.md` establishes that first release does not enable relay. Direct TCP/QUIC candidates are attempted; if they all fail, the caller receives explicit `PeerConnectionUnavailableException`, and no prompt, response or conversation history is sent through a central service.
- **Future byte-path design:** a later approved relay must forward opaque bytes beneath an end-to-end authenticated/encrypted channel. The relay must not terminate the endpoint security layer, parse/transform application messages, or log/persist payloads. The relay can observe PeerIds, network addresses and ports, reservation/connect outcomes, start/end times and duration, byte counts, payload sizes and timing/rate patterns; it cannot promise anonymity.
- **Reason relay runtime is not enabled:** the upstream [.NET libp2p relay README](https://github.com/NethermindEth/dotnet-libp2p/blob/main/libp2p/Libp2p.Protocols.Relay/README.md) describes a critical stream-bridging gap. A control-plane reserve/connect response does not prove a working relayed application byte stream. The current product transport does not opt into `WithRelay()`.
- **Regression guard:** `tests/test_relay_privacy_boundary.py` verifies the current host stack remains direct-only, exhaustion fails closed, the future relay requires opaque end-to-end protected bytes, metadata visibility is documented, and the decision is registered.
- **Exact-head verification:** Step Three quality gate passed on V 3.0.359; all 159 Python tests passed, including each of the four new relay privacy tests. Graph structure and output/evidence checks also passed. [Quality gate](https://github.com/artinrahimii/project/actions/runs/40450008797) · [Test job log](https://github.com/artinrahimii/project/actions/runs/40450008797/job/122010271159).
- **Dependency review:** `T0118 → T0119` and `T0115 → T0119` remain validated `sequencing_only` edges. `T0119 → T0120` is validated as `contract_or_interface_dependency` because the next announcement/rendezvous service must consume the metadata-only boundary. All original `blocks` edges remain.
- **Scope:** `T0119` is complete as a design/policy deliverable. This is **not** a claim that relay byte forwarding has been implemented or tested. Any future runtime relay needs a real three-peer encrypted byte-stream test as defined in ADR-0004.
- **Next task:** `T0120`, metadata-only peer announcements and capability discovery.
