- **Implementation:** `Libp2pPeerTransport.cs` registers libp2p QUIC and publishes both TCP and QUIC/UDP direct listen addresses under the same local PeerId.
- **Fallback implementation:** `PeerTransportFallbackConnector.cs` tries an ordered list of `PeerTransportEndpoint` candidates. Every candidate must pin the same expected PeerId; duplicate addresses are skipped; failed transports are disposed; the chosen connection returns its selected endpoint and failure count. Final failure is explicit and stores only address and exception type, never exception messages or payloads.
- **Privacy boundary:** the connector handles addresses and peer identities only. It has no request/response arguments and does not contact or forward traffic through a rendezvous service. Application messages go directly over the selected authenticated peer transport.
- **Real acceptance added:** existing TCP loopback exchange is retained. A second real two-peer scenario first attempts a refused TCP address and then the same peer's QUIC/UDP address; request and response byte arrays must round-trip over QUIC. A mixed expected-peer-identity candidate list is rejected before a transport is created.
- **Linux test prerequisite:** the HostLifecycle workflow installs Microsoft's `libmsquic` native runtime before running the QUIC integration.

- **Limitations:** this is a real alternative direct transport when TCP is unavailable but direct UDP/QUIC remains reachable. It does **not** promise hole punching or traverse networks where NAT/firewall rules block both paths.
