# T0186 — رضایت آگاهانه و هشدار حریم خصوصی پیش از اعتماد به همتا

- **وضعیت:** در حال اجرا؛ پیاده‌سازی افزوده شده است، اما پذیرش exact-head CI هنوز تأیید نشده است.
- **مبنای بررسی:** مخزن artinrahimii/project، شاخه main، commit 6b507bba948743fe7da5cf3d4d4f9925601f24a7، نسخه V 3.0.872.
- **تلاش:** T0186-A001 — بازبینی یال‌ها و افزودن متن رضایت به جریان اعتماد Android و فعال‌سازی میزبانی Windows.
- **پیش‌نیازها:** T0185 و T0177 در گراف done هستند و خروجی/آزمون‌های ثبت‌شدهٔ آن‌ها بررسی شد.
- **بازبینی وابستگی‌ها:**
  - T0185 → T0186: به sequencing_only / validated تغییر طبقه‌بندی یافت. T0185 قرارداد مجوزهای Android را کنترل می‌کند؛ UI رضایت T0186 از مجوز runtime یا خروجی verifier استفاده نمی‌کند.
  - T0177 → T0186: به sequencing_only / validated تغییر طبقه‌بندی یافت. T0177 آزمون‌های سقف تلاش/dispatch را ارائه می‌کند؛ T0186 فقط پیش از trust/save رضایت می‌گیرد و قرارداد dispatcher را تغییر نمی‌دهد.
  - نوع اصلی هر دو یال blocks و ترتیب محافظه‌کارانه حفظ شد. هیچ یالی حذف نشد.
- **پیاده‌سازی Android:** دیالوگ trust اکنون PeerId دقیق را نشان می‌دهد و افشا می‌کند که میزبان prompt و capsule را پس از transport decryption می‌بیند؛ اعتماد ذخیره‌شده، درخواست را خودکار ارسال نمی‌کند. متن supporting برای prompt نیز capsule و محدودیت رمزگذاری انتقال را روشن می‌کند.
- **پیاده‌سازی Windows:** پیش از ساخت/شروع سرویس peer-host، یک MessageBox با پیش‌فرض No رضایت صاحب دستگاه را می‌گیرد. رد آن toggle را خاموش نگه می‌دارد و سرویس ایجاد نمی‌شود؛ تأیید هویت PeerId همچنان جداگانه باقی می‌ماند.
- **کد مشترک/آزمون:** متن Windows در Shared.Security قرار دارد؛ آزمون HostLifecycle و Python برای متن و ترتیب اجرا افزوده شدند.
- **مستندات:** بخش T0186 به docs/security.md افزوده و توضیح قدیمی pending مربوط به T0185 با نتیجهٔ واقعی جایگزین شد.
- **آزمون‌ها:** در این commit هیچ نتیجهٔ CI موفق ادعا نمی‌شود؛ آزمون‌های exact-head محصول و کیفیت در انتظارند.
- **محدودیت:** نمایش رضایت، تضمین رفتار طرف مقابل، حذف logهای سیستم‌عامل/نرم‌افزار ثالث یا اثبات end-to-end مسیر شبکه نیست.
- **گام بعدی:** اجرای workflowهای محصول و کیفیت روی commit این تغییر؛ پس از بررسی نتیجه‌ها، فقط با شواهد واقعی وضعیت را به done تغییر بده.
