## Root cause
The .NET libp2p factory performs the standard Identify session protocol (/ipfs/id/1.0.0) inside ConnectedTo before publishing the connected-session event. Its OnConnected callback therefore does not fire until Identify succeeds. The Android host previously registered only the White-P application protocol, so it could not answer the .NET host's mandatory Identify request. This matches the three .NET fixture processes remaining at WAITING_FOR_REMOTE_SESSION.

## Implementation
- Registered the JVM library's standard Identify() binding on the Android libp2p host.
- Kept the White-P /white-p/peer-message/1.0.0 binding and framing unchanged.
- Added a Python source-contract regression test that requires Identify to remain registered before the application binding.
