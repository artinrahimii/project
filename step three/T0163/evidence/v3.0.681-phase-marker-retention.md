# T0163-A055 — retain lifecycle markers independently

## Baseline
- Commit: `c2b6f68dff668cdca8279275e9cd9421ef9b042d` (`V 3.0.680`).
- Product workflow: [run 41176392991](https://github.com/artinrahimii/project/actions/runs/41176392991).
- Android JVM report artifact: `13033665980`, 44,126 bytes, SHA-256 `0ae2659afd8439dca681b4d0eec9ecb50e8a8ab33c79ab909c1bca6f90ebb5ef`.
- The exact-head Android JVM suite reported 105 tests, 104 passed and one failure in the three-native-.NET-peer correlated request/response test.

## Finding
The test placed fixed lifecycle markers and diagnostic records in the same concurrent queue. On failure, it called `takeLast(60)` over that combined queue. Since diagnostics are emitted at a much higher frequency than lifecycle markers, earlier markers could be dropped from the failure report. The captured tail therefore was insufficient to identify the earliest missing phase.

## Change
- Fixed lifecycle markers now go to `phaseOutput` and are all retained for the assertion report.
- Payload-free diagnostic lines go to a separate `diagnosticOutput` queue and remain capped.
- Failure text includes both complete phase markers and the last 60 diagnostics.
- The Python source-contract check now guards the separation and prevents reintroducing truncation of lifecycle markers.

## Scope and limits
This is test-harness observability work only. No production behavior or acceptance criteria were relaxed. The underlying cross-runtime failure is not yet fixed and `T0163` remains in progress. No local Android, .NET or Python suite was run in this editing session; exact-head CI for `V 3.0.681` is required.
