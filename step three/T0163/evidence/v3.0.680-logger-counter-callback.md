# T0163-A054 — Fix diagnostic logger counter ownership

- **Base commit:** `389ba82e0512c46e5bbd3289df7c409475ee9863` (`V 3.0.679`).
- **Attempt:** A054; T0163 remains `in_progress`.
- **Preconditions:** T0160 and T0162 remain done; their validated incoming edges to T0163 are unchanged.

## Failure being corrected

Exact V 3.0.679 CI failed compilation at `AndroidInteropPeerServer.cs(112,71)` with C# `CS0120`. The nested logger attempted to access `_written`, an instance field on `InteropDiagnosticLoggerProvider`, without an instance. No Android JVM interop test ran.

## Code correction

`InteropDiagnosticLoggerProvider.CreateLogger` now passes a closure `() => Interlocked.Increment(ref _written) <= 80` into the nested logger. `InteropDiagnosticLogger` receives the closure as `Func<bool> allowWrite` and calls it before writing a diagnostic record. This preserves the 80-record cap per provider without a static counter or exposing the private field.
The logger still emits only category, log level, event ID, static `{OriginalFormat}` template and exception type. It does not call the formatter or emit structured argument values.
A Python source-contract regression now checks the provider-scope callback, `Func<bool>` parameter and callback invocation.
