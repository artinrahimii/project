# T0163-A043 — Android to Windows .NET libp2p interoperability

**Commit under test:** `V 3.0.669` (exact-head CI pending)

## Deliverable

A test-only .NET peer fixture uses the repository's production `Libp2pPeerTransport` and shared `/white-p/peer-message/1.0.0` protocol. It trusts only the Android test client's supplied PeerId, listens on loopback, parses the generated Protobuf inference request, checks the response correlation contract, and responds over the authenticated peer stream.

The Android JVM integration test starts three independent .NET peers, resolves their actual loopback multiaddresses, dispatches one shared request through `AndroidInferenceRequestRuntime`, and checks three distinct per-host attempt IDs, three distinct ephemeral host IDs, and one correlated response from each .NET peer.

## CI execution

The Android CI job builds the .NET fixture, installs its MsQuic runtime, and sets `WHITEP_INTEROP_SERVER_DLL` when executing `testDebugUnitTest`. Thus the test is not skipped in the configured CI job. Local JVM test runs without that environment variable skip only this native-process integration test.

## Scope and limitations

The fixture exercises the production .NET libp2p transport/protocol and response-correlation validator, but its response body is a deterministic test value, not the result of a loaded GGUF model. The separate exact-head local-model acceptance workflow covers llama.cpp process execution. This fixture also uses loopback and does not prove public Internet reachability or a production rendezvous deployment. Those remain separate acceptance gates.
