# T0163-A052 — correct the .NET READY tab delimiter

**Base commit:** \`408ada2a7e9da5e60e4be361f29bb2e85f49733d\` (\`V 3.0.677\`).

## Verified failure

The exact-head product run failed the Android JVM suite: 104 of 105 tests passed. The three-peer .NET test timed out while awaiting the fixture's READY record. KtLint, debug APK build, .NET fixture compilation, Windows WPF and HostLifecycle passed. Step Three quality and live local-model inference integration passed.

## Root cause

The fixture writes a tab-delimited line:
\`READY<TAB>PeerId<TAB>TCP multiaddress\`.

In \`AndroidInteropPeerServer.cs\`, the C# interpolated string uses the tab escape \`\\t\`. The Kotlin reader had \`line.startsWith("READY\\\\t")\`, which searches for a literal backslash followed by \`t\`, not a tab. The reader therefore never completed \`readyLineFuture\`, and the test stopped before submitting requests.

## Correction

- Change the Kotlin source to \`line.startsWith("READY\\t")\`.
- Keep \`readyLine.split('\\t')\` to extract the PeerId and address fields.
- Add a Python source-contract regression asserting the single-escaped Kotlin form and rejecting the double-escaped form.
- Preserve all three-peer dispatch, authentication, request-validation and response-correlation assertions.

## Verification status

The fix is committed with the exact-head CI pending. This evidence does not claim T0163 is complete. The task remains \`in_progress\` until the Android-to-.NET three-peer test receives and correlates every response.
