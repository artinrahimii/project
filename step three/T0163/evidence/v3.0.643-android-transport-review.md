# T0163 — Android libp2p source review at V 3.0.643

- Base: `8eb150c960f24f38a42cacae67002b3e8c0f0478`; task status remains `in_progress`.
- New implementation reviewed:
  - `AndroidPeerIdentityStore.kt`: stable Ed25519 PeerId; private-key envelope protected with Android Keystore AES-GCM; corrupt/missing-key records fail closed.
  - `AndroidPeerTrustStore.kt`: canonical PeerId records protected separately; trust requires the explicit-confirmation API; revoke operation exists.
  - `RendezvousPeerDirectoryClient.kt`: HTTPS metadata-only directory, exact PeerId/address binding, bounded response and expiry checks.
  - `Libp2pInferenceRequestTransport.kt`: JVM libp2p direct TCP/NoiseXX/Mplex host, the Windows application protocol ID `/white-p/peer-message/1.0.0`, existing varint framing, Protobuf request and a pending correlated-response map.
  - `Libp2pInferenceRequestTransportTest.kt`: a same-library, two-peer TCP/Noise loopback exchange checks request/response correlation.
- Product-code boundary still open:
  - Repository code search found the transport class only at its declaration and its loopback test; no production composition root currently passes it into `InferenceAttemptDispatcher`. The dispatcher remains an injected port and no caller was found.
  - The Android trust store exposes an explicit approval method but no enrollment/pairing UI calls it. The WPF enrollment UI is also not present; an operator-approved Android PeerId needs a real pairing path before the new adapter can connect to a Windows host.
  - The current automated peer test uses two JVM libp2p peers in one test process. It is not a .NET `Nethermind.Libp2p` interoperability test and does not prove Windows-host inference receipt.
  - No physical-device Android Keystore test, independent-network host, production rendezvous deployment or public reachability proof was available in this run.
- Therefore the new sources are real implementation output, but T0163 is not accepted as done. The next integration gates are production dispatcher wiring, explicit cross-platform peer enrollment, .NET/Android protocol interoperability, and an actual correlated Windows-host response test.
