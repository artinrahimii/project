# T0163-A047 — Android/Windows libp2p multiplexer interoperability

**Base commit:** `7859b54e953c2a2de2fe5df5bedc19da492351a8` (`V 3.0.672`).

## Exact V 3.0.672 failure

The Android JUnit report artifact `13030160630` (43,215 bytes) reports:
- `dispatchesOneSharedRequestWithDistinctAttemptsOverAuthenticatedPeerStreams`: passed.
- `sendsAndReceivesCorrelatedResponseOverAuthenticatedNoiseTcpStream`: passed.
- `dispatchesRoundToThreeNativeDotNetLibp2pHosts`: failed. All three attempts were `REJECTED`, with `await_peer_stream:ExecutionException`; the test did not reach request/response correlation assertions.

KtLint and debug APK build passed. Windows WPF and HostLifecycle passed. Step Three graph/Python quality passed.

## Root-cause evidence

The Android dependency is pinned to `io.libp2p:jvm-libp2p:1.3.7-RELEASE`. Its versioned source:
- `Builders.kt` chooses `StreamMuxerProtocol.Mplex` as the Standard default when no muxers are supplied.
- `StreamMuxerProtocol.kt` provides both `Mplex` (`/mplex/6.7.0`) and `getYamux()` (`/yamux/1.0.0`).

Sources:
- https://github.com/libp2p/jvm-libp2p/blob/1.3.7/libp2p/src/main/kotlin/io/libp2p/core/dsl/Builders.kt
- https://github.com/libp2p/jvm-libp2p/blob/1.3.7/libp2p/src/main/kotlin/io/libp2p/core/mux/StreamMuxerProtocol.kt

The Windows project pins `Nethermind.Libp2p` 1.1.0. The adapter constructs the peer through `AddLibp2p` and does not override its stream muxer. The corresponding builder implementation exposes `YamuxProtocol` as its stream muxer:
- https://github.com/NethermindEth/dotnet-libp2p/blob/main/libp2p/Libp2p/Libp2pPeerFactoryBuilder.cs
- https://github.com/NethermindEth/dotnet-libp2p/blob/main/libp2p/Libp2p.Core/PeerFactoryBuilderBase.cs

Thus the Android Standard default (Mplex only) and Windows .NET default (Yamux only) have no common TCP stream multiplexer. This is consistent with the cross-runtime stream-open failure while Android↔Android tests pass.

## Implementation

The Android libp2p host now explicitly advertises Yamux first and Mplex second:
- Yamux is common with the Windows .NET host.
- Mplex remains available for backward compatibility with existing JVM/libp2p peers.
- Existing Noise XX secure-channel negotiation, peer trust checks, directory identity checks, application protocol, framing and response correlation are unchanged.
- No new dependency was added.
- Added a Python source-contract test that asserts both muxers are configured and Yamux is listed first.
- The existing real three-native-.NET-peer test remains unchanged and still requires three queued requests and three correctly correlated responses.
