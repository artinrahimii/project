# ADR-0016: Maintained libp2p cryptographic transport

- **Status:** Accepted for the maintained host/Android libp2p cryptographic transport boundary. CI-verified Android-to-Windows fixture interoperability is present; physical end-to-end and public-network acceptance remain pending.
- **Date:** 2026-10-27
- **Related task:** T0129.
- **Implementation:** `Nethermind.Libp2p` and `Nethermind.Libp2p.Core` are pinned to version `1.1.0`. The existing host transport delegates secure-channel establishment and peer authentication to the library's libp2p Noise/TLS stack. The shared `PeerSecurityPolicy` centralizes normalized PeerId input checks and delegates actual PeerId parsing to the library's `PeerId` implementation.
- **Why:** transport cryptography and peer identity encoding must remain in a maintained, interoperable implementation instead of application-authored key exchange, cipher, signature, or hash algorithms. NuGet lists `Nethermind.Libp2p` 1.1.0 as a released package last updated on 2026-10-20; the repository previously pinned 1.0.3. The new version is verified by the exact-commit quality and product workflows before task completion.
- **Runtime boundaries:** this is not an independent cryptographic audit, proof of every transitive dependency's vulnerability status, verified public reachability, NAT traversal, or physical Android-to-Windows acceptance. Persistent private-key protection and explicit enrollment/trust UX are separately implemented and reviewed in ADR-0017/ADR-0018. The code-level identity parser does not replace authenticated handshake verification; both Android and `Libp2pPeerTransport` pin and verify the expected peer identity. Android CI now exercises the Android production runtime against the Windows .NET libp2p fixture, but that fixture is not a physical independent-node deployment. `AC-P2P-01` remains **NOT RUN** until physical end-to-end evidence exists.
- **Traceability:** `src/Host.Windows/Networking/Libp2pPeerTransport.cs`, `src/Host.Windows/Networking/Libp2pPeerMessageProtocol.cs`, `src/Shared.Security/PeerSecurityPolicy.cs`, `src/Shared.Security/WhiteP.Shared.Security.csproj`, `tests/HostLifecycle.Tests/PeerSecurityPolicyAcceptanceTests.cs`, `tests/HostLifecycle.Tests/PeerTransportContractAcceptanceTests.cs`, `tests/test_crypto_library_policy.py`, `tests/HostLifecycle.Tests/Program.cs`, and `.github/workflows/product-build.yml`.


## Android interoperability revalidation — 2026-11-10 (UPD-S1-016)

The cryptographic boundary is provided by maintained libp2p implementations and Noise/TLS secure-channel negotiation; the application adds no custom cryptographic algorithms. The Android CI builds the Windows .NET peer fixture and exercises authenticated request/response, cancellation and sequential peer retry using the production Android runtime. This establishes CI fixture wire interoperability, not an independent security audit or real-world reachability guarantee. First-release relay remains disabled; direct connection failures are surfaced to the user as network-unavailable results. Physical Android handset-to-installed-Windows-host acceptance remains a separate requirement.
